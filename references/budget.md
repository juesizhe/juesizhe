# 觉思者 · Token 预算与降级策略

> 没有度量，就谈不上「有限额度下更快」。本页定义三件事：**每场记什么**、**额度紧时保谁**、**什么时候机器自己降级**。

---

## 一、每场必须记录的三个数

推演收尾时，在 `PHILOSOPHY.md` 推演日志追加一行预算字段：

```
预算｜输入：<估算 token> ｜ WebSearch：<次数> ｜ 本地推理：<次数> ｜ 采纳：<Pn/驳回>
```

估算不需要精确：Token 用「打开文件字节数 × 0.62」即可（脚本 `scripts/build_deduce.py --check` 已代算）。

## 三、降级档（额度百分比指当日/当月剩余额度）

| 剩余额度 | 保留场次 | 说明 |
|---|---|---|
| **>60%** | 夜间批处理 + 白天批处理 + 周度精炼 | 全速，日产 6–7 题候选 |
| **30–60%** | 只留**白天本地批处理**（电费替代 token）+ 周度精炼 | 云端只做汇总裁决 |
| **<30%** | 暂停新议题，转**众包消化期** | 把积压议题挂出去等人推翻 / 补源；来什么推什么 |

**硬规则**：

1. 夜里 23:05 的精炼**不是每天都必做**——日產命题 ≤1 条时可直接跳过；`CORE.md` 整份重写是全局最贵的一步，默认改为**每周六一次**。
2. 任何一场若本地推理服务不可用，计 0 轮、立刻结束，**不重试多次**。
3. 机检（`scripts/contrib_check.py`）不通过的草稿，**不得**为了让它通过而反复重写——直接记为驳回。

---

## 四、谁最贵，谁最便宜（按此顺序下刀）

1. **最贵**：整份重写 `CORE.md`（需通读全库 + 生成全文）→ 降频到周度。
2. **次贵**：为同一议题反复 WebSearch → 先查 `references/evidence_ledger.md`。
3. **中**：每场重复加载同一套规则 → 已由 `prompts/deduce.md` 解决。
4. **最便宜**：本地 qwen3:14b（只有电费）→ 尽量把发散、自我反驳、初稿都放这里。
5. **零成本**：命题卡生成、机判定校验、Schema 检查——全是纯脚本。

---

## 五、自动降级触发（建议）

在夜间 / 白天批处理提示词里加一句自检：

> 若本场开始前发现当日已完成 ≥2 次落成推演，或距上次结算的剩余额度低于 60%，
> 则本场**只做一件最便宜的事**：跑 `deduction_memory.py status` + `summary-check`，
> 在 `PHILOSOPHY.md` 追加一行「降级：本场跳过」后结束，不发起新推理。

这样即便额度意外耗尽，也不会出现「推演跑到一半被掐断、落库只落一半」的状态。
